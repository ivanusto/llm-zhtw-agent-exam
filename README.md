# 繁體中文 agent 能力小考卷

這是一份極輕量、完全自動化驗證的評測工具，用來快速檢查本機模型是否具備在繁體中文環境擔任 Agent 的基本資格。不需要人工評分，也不需要另一個模型當裁判。四個項目：

| 項目 | 量什麼 | 滿分 |
|---|---|---|
| [繁中十題](exam/zh10.md) | 答得對、守題目的格式要求，而且不吐簡體字 | 20 |
| [工具呼叫十輪](exam/tools.md) | 吐得出合法 JSON，欄位、型別與值都正確 | 10 |
| [多步 agent 三題](exam/agent.md) | 工具呼叫的順序對不對 | 3 |
| [JSON 緊湊度](exam/json-compact.md) | 被要求「不要有其他文字」之後守不守規矩 | 比數（預設 50 輪） |

## 設計初衷

多數公開基準偏向衡量英文能力上限，這份測試只聚焦在兩件事：繁體中文可用性與 AI Agent 規矩。

英文分數再高的模型，只要輸出繁中時夾帶簡體字、或思考過程汙染輸出，在台灣的產品環境就比較不好被使用。此外，正確率高的模型不一定懂得節省 Token，JSON 緊湊度就是用最低成本快速檢視模型是否守規矩。

## 評測極限

在 v1 判準下，現行主流模型通常能在前三項拿到滿分，因此只能篩掉明顯不合格的模型，無法評鑑高下。v2 判準收緊了前三項（見下節），但鑑別度主要仍在第四項。

真正具有鑑別度的是 JSON 緊湊度。實測同級距模型在該項目會出現極大落差，且表現與推理正確率無直接關聯。實測數字與除錯過程見：

- [results/day14.md](results/day14.md)：三顆模型，以及一個讓三顆模型都被誤扣一分的判分 bug
- [results/day15.md](results/day15.md)：五顆模型，以及三個方法學問題（vLLM 上貪婪解碼不可重現、十輪不夠、Day 14 有兩欄重現不出來）

## 判準版本

Day 14 與 Day 15 的數字都是 v1 判準。v2（2026-10）改了以下幾點，分數只會持平或變低，**兩版的數字不能直接比較**，輸出 JSON 的 `scoring` 欄位會標明版本。

- 繁中十題：除了關鍵字，也驗題目自己寫明的格式（一句話、少於五十字、每點一行、只回答數字加單位），第 10 題另驗數值範圍。簡體字表移除了十六個繁體也通用的字，例如繁簡同形的「旋」「浙」。
- 工具呼叫：除了欄位存在，也驗 `dir` 與 `max_results` 的值；`"max_results": true` 不再被當成整數；另報「裸 JSON」比數（回應沒有 markdown 圍籬或其他文字）。
- 多步 agent：題目列出工具的順序打亂。v1 列出的順序就是正確答案，照抄即可滿分。另報「只列工具名稱」比數。
- JSON 緊湊度：預設改為 50 輪、每 10 輪一組報全距，欄位正確改為不得有多餘欄位。
- 腳本支援多輪（`--repeats`、`--rounds`），報中位數與全距，對應 Day 15 的做法。

## 怎麼跑

環境僅需 Python 3.8 以上的標準函式庫，支援任何相容 OpenAI `/v1/chat/completions` 的端點。

```bash
python3 scripts/exam.py         http://127.0.0.1:8000 <model> <label> --repeats 4
python3 scripts/json-compact.py http://127.0.0.1:8000 <model> <label>
```

執行細節、雲端 API 的用法，以及兩個地雷（關思考模式的開關名稱、為什麼 JSON 那題不能用貪婪解碼）寫在 [scripts/README.md](scripts/README.md)。

題目放在 `exam/*.json`，腳本從這裡讀；`exam/*.md` 是給人看的說明。改題目後跑 `python3 scripts/check-bank.py` 確認兩邊一致。
