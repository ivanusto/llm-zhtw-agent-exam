# 繁體中文 agent 能力小考卷

一份刻意做得很小、但完全機器可驗的考卷，用來檢查一顆本地模型
能不能在繁體中文環境下當 agent 的底模。四個項目：

| 項目 | 量什麼 | 滿分 |
|---|---|---|
| [繁中十題](exam/zh10.md) | 答得對，而且不吐簡體字 | 20 |
| [工具呼叫十輪](exam/tools.md) | 吐得出合法且欄位型別正確的 JSON | 10 |
| [多步 agent 三題](exam/agent.md) | 工具呼叫的順序對不對 | 3 |
| [JSON 緊湊度十輪](exam/json-compact.md) | 被要求「不要有其他文字」之後守不守規矩 | 比數 |

沒有一項需要人來評分，也沒有一項需要另一顆模型當裁判。

## 為什麼要有這種東西

多數公開基準是英文的，而且量的是能力上限。這份考卷量的是另外兩件事：

1. **繁體中文的可用性。** 一顆模型的英文分數再高，如果它答繁中時混進簡體字、
   或思考時切換語言把輸出汙染掉，在台灣的產品裡就是不能用。
2. **agent 禮儀而不是 agent 能力。** 正確率高的模型不一定省 token。
   JSON 緊湊度那一題就是專門考這件事，很便宜，但很誠實。

## 誠實揭露這份考卷的極限

2026 年這個級距的模型，前三項會全部滿分。實測過的三顆都是 20/20、10/10、3/3。
**它能篩掉明顯不合格的，但分不出好壞。**

有鑑別度的是第四項。同樣三顆模型在那一題上是 8/10、0/10、7/10，
而且方向跟正確率無關。

實測數字在 [results/day14.md](results/day14.md)，裡面也記錄了一個判分 bug 的除錯過程，
那個 bug 讓三顆模型都被誤扣了一分。

## 怎麼跑

只需要一個 OpenAI 相容的 `/v1/chat/completions` 端點，除了標準函式庫沒有相依套件。

```bash
python3 scripts/exam.py         http://127.0.0.1:8000 <model> <label>
python3 scripts/json-compact.py http://127.0.0.1:8000 <model> <label>
```

執行細節與兩個地雷（關思考模式的開關名稱、以及為什麼 JSON 那題不能用貪婪解碼）
寫在 [scripts/README.md](scripts/README.md)。
