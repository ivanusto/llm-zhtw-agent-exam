## 三個方法學問題，這一輪才浮出來

### 一、貪婪解碼在 vLLM 上不可重現

同一題、`temperature=0`、同一個端點連跑六次，得到**六種不同輸出**（238 到 336 字元）。
連續批次會改變批次組成，MoE 的路由與 kernel 的歸約順序跟著變，邊際 token 就翻面。

所以「前四項用 temperature 0 所以可重現」這個前提在這個堆疊上不成立。
本輪 Ornith 兩欄改跑四輪並記錄全距，這也是 NVFP4 那個 19/20 之所以敢寫出來的理由：
它四輪是 19/19/19/20，不是單次抽樣的運氣。

### 二、十輪對這一題不夠

Day 14 用十輪。這次量了每十輪的散布：Ornith BF16 是 2–7、NVFP4 是 6–10。
**十輪分得開 0 與 5，分不開 5 與 7。** 所以這一列改成 5×10 = 50 輪，並記錄每十輪的全距。

### 三、Day 14 那一列有兩欄重現不出來

| | Day 14 記錄 | 本輪 50 輪 | 
|---|---|---|
| pplx 後訓練 | 0 / 10 | 0 / 50 ✅ 重現 |
| 原版 27B FP8 | 7 / 10 | **0 / 50** ❌ |
| Flash-Next | 8 / 10 | **24 / 50（48%）** ❌ |

原版 27B 那一欄另外排除了兩個變因：思考模式開與關都是 0/10，
取樣拉到 temp 1.0 / top_p 1.0 也只有 1/10。**沒有任何一組設定能重現那個 7。**

Day 14 對這一欄的紀錄不足以追查原因，這正是「引用比數時必須連取樣設定一起報」
這條規則存在的理由。**受影響的是 Day 14 第五關的結論**：當時把 0 對 7 的差距歸給
後訓練買到的格式紀律，但本輪兩顆 27B 都是 0/50，
所以那個紀律屬於 27B 這一家的底子，不是後訓練加上去的。

## 這一輪學到的

**「為 agent 而生」不等於格式守規矩。** Ornith 是五顆裡唯一明著掛 agent 招牌的，
JSON 緊湊度 24/50，跟 Flash-Next 打平，輸給兩顆 27B 的 0/50。
這重複了 Day 14 的結論並把它推得更遠：agentic 能力與 agentic 禮儀是兩件事。

**量化會同時傷繁中與格式紀律。** Ornith 的 BF16 與 NVFP4 兩份檢查點，
chat template、tokenizer、vocab、merges、generation config **逐位元相同**，
差異只在權重。NVFP4 那一檔繁中掉一分（四輪有三輪洩漏簡體字），
JSON 多行從 24/50 升到 40/50。同一顆模型、同一份考卷，
壓到 4 bit 之後兩個維度一起退。這是這份考卷第一次分出高下，而且分在量化軸上。
